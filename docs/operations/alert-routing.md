# Alert Routing

Use these alerts for pilot-stage operations. Thresholds are intentionally conservative and should be tuned after real baseline traffic is available.

| Alert name | Signal/query | Threshold | Route/owner | First response action | Escalation note |
| --- | --- | --- | --- | --- | --- |
| API health down | HTTPS uptime check against API health endpoint | 2 consecutive failures or 2 minutes down | Primary API operator | Check API service status, recent deploys, and host incidents. | Escalate Sev1 if pilot-critical users cannot access API. |
| Readiness/database unavailable | `sum(increase(clinicpulse_readiness_checks_total{result!="success"}[2m])) >= 2` or request logs where `route="/readyz"` and `status=503` | Page only after at least 2 failed readiness checks in 2 minutes; use a lower-priority warning for 1 failure in 5 minutes | API/database operator | Check managed Postgres status, connection limits, recent migrations, and readiness duration via `clinicpulse_readiness_check_duration_seconds_count` / `clinicpulse_readiness_check_duration_seconds_sum`. | Escalate Sev1 if authenticated workflows are blocked. |
| 5xx rate elevated | `(sum(increase(clinicpulse_http_requests_total{status_class="5xx"}[10m])) / sum(increase(clinicpulse_http_requests_total[10m]))) > 0.02 and sum(increase(clinicpulse_http_requests_total[10m])) >= 100` | Above 2% over 10 minutes with at least 100 total requests in the same window | API operator | Break down by `route`, `method`, `principal_type`, and log `error_code`; compare with deploy time. | Escalate Sev2, Sev1 if broad outage. |
| p95 latency elevated | `histogram_quantile(0.95, sum by (le, method, route, status_class, principal_type) (rate(clinicpulse_http_request_duration_seconds_bucket[5m])))` | Above 1.5s for 15 minutes | API operator | Check slow routes, database latency, and host resource saturation; use `clinicpulse_http_request_duration_seconds_count` and `clinicpulse_http_request_duration_seconds_sum` for volume/context. | Escalate Sev2 if user-visible workflow timeouts occur. |
| HTTP categorized errors elevated | `sum by (error_kind) (increase(clinicpulse_http_errors_total[10m]))` | 10 errors in 10 minutes or 3x baseline for one `error_kind` | API operator | Identify dominant `error_kind`, affected route from request metrics, and matching request IDs in logs. | Escalate according to user impact. |
| Login throttling spike | `sum(increase(clinicpulse_domain_operations_total{operation="auth.login",result="rate_limited"}[10m]))` | 20 events in 10 minutes or 3x baseline | Auth/API operator | Determine abuse vs legitimate lockout and inspect origin/rate-limit config. | Escalate if legitimate pilot users cannot log in. |
| Login failures/errors elevated | `sum by (result) (increase(clinicpulse_domain_operations_total{operation="auth.login",result=~"invalid_credentials|error"}[10m]))` | 20 failures in 10 minutes or any `error` result count above 2 in 10 minutes | Auth/API operator | Separate invalid credentials from system errors and check auth/database health. | Escalate if login errors block legitimate pilot users. |
| CSRF denials spike | `sum(increase(clinicpulse_csrf_denials_total{result="denied"}[10m]))` plus `sum by (error_kind) (increase(clinicpulse_http_errors_total{error_kind="csrf"}[10m]))`; correlate with request completion logs by request ID/time window, route, status, and origin context where available. | 10 events in 10 minutes or sudden new origin | Auth/API operator | Check `CLINICPULSE_TRUSTED_ORIGINS`, frontend deployment origin, and affected request completion logs. | Escalate after deployment-origin mismatch is confirmed. |
| Report creation errors elevated | `sum by (result) (increase(clinicpulse_domain_operations_total{operation="report.create",result=~"validation_error|error"}[15m]))` | 5 errors in 15 minutes or 3x baseline | Operations data owner | Check whether field reporting users are blocked and inspect validation/error split. | Escalate Sev2 if pilot reporting is blocked. |
| Report review errors elevated | `sum(increase(clinicpulse_domain_operations_total{operation="report.review",result="error"}[15m]))` | 3 errors in 15 minutes | Operations data owner | Check admin review workflow and database health. | Escalate if pending review queue cannot be processed. |
| Offline sync failures elevated | `sum(increase(clinicpulse_domain_operations_total{operation="offline_sync",result="error"}[15m]))` or sync error logs | 5 failures in 15 minutes or 2 affected districts | Operations data owner | Identify source, district, and whether stale data is user-visible. | Escalate Sev2 when clinic freshness is affected. |
| Webhook failures elevated | `sum(increase(clinicpulse_domain_operations_total{operation="partner.webhook_test",result=~"failed|error"}[15m]))` | 3 failures for one partner in 15 minutes | Partner integration owner | Check partner endpoint, timeout, delivery-enabled setting, and request completion logs by request ID/time window. | Escalate to partner contact if persistent. |
| Export generation failures | `sum(increase(clinicpulse_domain_operations_total{operation="partner.export",result="error"}[30m]))` | 2 failures in 30 minutes | Partner/export owner | Identify export type, partner, input data freshness, and request completion logs by request ID/time window. | Escalate if pilot reporting deadline is affected. |
| Stale clinic count elevated | Admin/data-ingestion operational check by district/source, or provider-derived monitor if configured | Any critical clinic stale beyond pilot freshness target, or 5 clinics stale in one district | Operations data owner | Confirm source freshness and pause dependent partner export if needed. | Escalate Sev2 if public/operator decisions may be stale. |

## Alert Destination Defaults

- Sev1 and Sev2: page or direct-message the primary operator and post in the pilot incident channel.
- Sev3: route to the owning operator queue with same-business-day review.
- Sev4: record for maintenance review.
- Every alert should include environment, service, route or component, threshold, current value, and a dashboard/log link.
